03이슈를 고른 방법

유명한 프로젝트라고 외부 PR이 잘 머지되는 건 아닙니다. 요즘은 AI로 만든 PR이 쏟아져서, 큰 저장소일수록 외부 PR 대부분이 닫히거나 방치됩니다. 그래서 세 단계를 거쳐 기여할 곳을 골랐습니다.

  1. 외부 PR이 실제로 머지되는 곳 찾기

    저장소 61곳에서 6/30~8/28에 fork로 올라온 외부인 PR을 9/27까지 추적했습니다. 메인테이너와 봇, PR을 많이 낸 사람은 뺐습니다.

  2. 기여 규칙 확인하기

    이슈에 할당되지 않은 PR을 봇이 자동으로 닫는 곳, CLA·DCO 서명이 필요한 곳, AI로 쓴 코멘트를 금지하는 곳을 걸러냈습니다.

  3. 막 올라온, 아무도 가져가지 않은 이슈

    좋은 이슈는 몇 시간 안에 누군가 가져갑니다. 담당자도, 연결된 PR도, 본문이나 코멘트의 "제가 할게요" 표현도 없는 이슈만 남겼습니다.

04기여는 이런 순서로 진행됐다

두 PR 모두 같은 순서를 따랐습니다. 순서가 중요한 건 2번과 6번입니다. 먼저 직접 재현해서 원인을 확인한 뒤에, 이슈에 "제가 하겠다"고 알렸습니다.

  1. 이슈 읽기
  2. 격리된 환경에서 재현
  3. 원인 찾기
  4. 코드 수정
  5. 테스트·린트
  6. 이슈에 코멘트
  7. fork·브랜치 push
  8. 템플릿에 맞춘 PR
  9. CLA 또는 DCO
  10. 메인테이너 리뷰
  11. 머지·릴리스
첫 기여자가 겪는 대기 시간

첫 PR은 테스트 CI가 바로 돌지 않습니다. GitHub가 처음 기여하는 사람의 fork PR에는 메인테이너 승인(action_required)을 요구하기 때문입니다. 그래서 로컬에서 CI와 같은 검사를 미리 돌려 두는 것이 중요합니다.

05이 문서를 읽는 법

각 PR 페이지는 같은 순서로 되어 있습니다.

  1. 한 줄 요약: 문제, 원인, 해결을 세 줄로
  2. 먼저 알아둘 개념: 처음 보는 용어를 쉬운 말로
  3. 무슨 문제였나 → 원인 → 해결: 실제 코드와 그림으로
  4. 검증과 결과: 무엇을 확인했고 어떻게 머지됐는지
  5. 스스로 설명해보기: 면접에서 나올 만한 질문과 답

마지막 질문들은 답을 펼치기 전에 먼저 소리 내어 설명해 보세요. 막히는 부분이 다시 읽어야 할 부분입니다.
