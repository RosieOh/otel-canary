01한 줄 요약

  • 문제OpenTelemetry Python 1.45가 나온 뒤, Phoenix로 트레이스를 HTTP로 보내도록 설정하면 register()를 부르는 순간 AttributeError로 앱이 죽었습니다.
  • 원인Phoenix가 exporter 객체의 내부 속성 _headers를 직접 읽고 있었는데, 1.45에서 이 값이 exporter._client._headers로 옮겨졌습니다.
  • 해결두 위치 모두에서 헤더를 읽는 헬퍼를 만들고, 1.45에서 새로 섞여 들어온 기본 헤더는 걸러 출력이 예전과 같게 했습니다. 메인테이너가 다듬어 머지했고, 같은 날 0.17.2로 배포됐습니다.

02먼저 알아둘 개념

Arize Phoenix
LLM 앱을 들여다보는 오픈소스 관측성(Observability) 도구입니다. 어떤 프롬프트를 보냈고, 어떤 응답이 왔고, 시간이 얼마나 걸렸는지를 기록해서 화면에 보여줍니다. 스타는 1.1만 개입니다.
OpenTelemetry (OTel)
트레이스·메트릭·로그를 모으는 업계 표준입니다. 앱 안의 작업 하나하나를 span이라는 기록으로 남기고, 이를 수집 서버로 보냅니다. Phoenix도 이 표준으로 데이터를 받습니다.
Exporter
만들어진 span을 서버로 배달하는 부품입니다. 배달 방식에 따라 HTTP exporter(Phoenix는 6006 포트의 /v1/traces)와 gRPC exporter(4317 포트)가 있습니다.
register()
phoenix.otel.register()는 Phoenix용 OTel 설정을 한 줄로 끝내주는 함수입니다. TracerProvider, SpanProcessor, exporter를 한 번에 조립하고, 설정 요약(주소, 전송 방식, 헤더)을 배너로 보여줍니다.
헤더 마스킹
exporter는 인증 토큰 같은 헤더를 붙여 보냅니다. 배너에 토큰이 찍히면 안 되니까, 값은 ****로 가리고 헤더 이름만 보여줍니다.
밑줄(_)로 시작하는 속성
파이썬에서 "내부용이니 밖에서 쓰지 말라"는 약속입니다. 라이브러리는 이런 속성을 예고 없이 바꿔도 됩니다. 이번 버그가 바로 여기서 나왔습니다.

04무슨 문제였나

신고자와 같은 조건을 격리된 가상환경에 만들었습니다. arize-phoenix-otel 0.17.1과 OpenTelemetry 1.45.0을 설치하고, Phoenix 서버 주소(HTTP)로 트레이스를 보내도록 설정했습니다.

재현 코드

from phoenix.otel import register

register(
    project_name="repro",
    endpoint="http://localhost:6006/v1/traces",   # HTTP로 전송
    headers={"authorization": "Bearer secret"},
)

배너를 끄는데도 왜 죽었나

register()는 배너 문자열을 항상 만들고, 출력 여부만 verbose로 정합니다. 배너를 만드는 과정에서 헤더를 읽다가 터지니, 출력을 꺼도 소용이 없었습니다.

details = tracer_provider._tracing_details()   # verbose와 상관없이 항상 실행
if verbose:
    print(f"{details}{global_provider_msg}")   # 출력만 조건부
return tracer_provider
영향 범위

Phoenix 서버 주소로 HTTP 전송을 설정한 사용자는 register() 한 줄에서 앱이 멈췄습니다. 게다가 phoenix-otel은 OTel 버전에 상한을 두지 않아서, 새로 설치하는 사람은 모두 1.45를 받게 되는 상황이었습니다.

05원인: 헤더가 다른 서랍으로 옮겨졌다

Phoenix는 배너에 헤더를 보여주려고 exporter 객체의 _headers라는 서랍을 직접 열어보고 있었습니다. 그런데 OTel 1.45에서 HTTP exporter가 새 공용 HTTP 클라이언트를 쓰도록 바뀌면서, 헤더가 _client라는 다른 서랍 안으로 옮겨졌습니다. 밑줄로 시작하는 내부용 속성이라, OTel 입장에서는 예고 없이 옮겨도 되는 부분이었습니다.

1.45는 헤더를 이렇게 합친다

OTel 1.45 코드를 직접 열어보니, 사용자 헤더에 exporter 기본 헤더(content-type, user-agent)와 환경변수 헤더를 합쳐 클라이언트에 넘기고 있었습니다. 압축을 켜면 클라이언트가 content-encoding도 추가합니다.

opentelemetry/exporter/otlp/proto/http/_common/__init__.py (요약)

def _resolve_headers(headers, headers_env_var):
    headers_ = {k.lower(): v for k, v in _OTLP_HTTP_HEADERS.items()}  # content-type, user-agent
    env_headers = parse_env_headers(...)                               # 환경변수 헤더
    headers_.update(env_headers)
    if headers:
        headers_.update({key.lower(): value for key, value in headers.items()})  # 사용자 헤더
    return headers_
gRPC 사용자는 왜 괜찮았나

이번 리팩터링(#5389)은 HTTP exporter만 바꿨습니다. gRPC exporter에는 _headers가 그대로 남아 있어서 아무 문제가 없었습니다.

06해결: 제출한 코드

배너를 만드는 곳에서 헤더를 직접 읽지 않고, 헬퍼 함수를 거치게 바꿨습니다.

packages/phoenix-otel/src/phoenix/otel/otel.py · 호출하는 곳

-  headers = _printable_headers(exporter._headers)
+  headers = _printable_headers(_exporter_headers(exporter))

새로 추가한 헬퍼 (docstring 생략)

# Headers the OTLP HTTP exporter sends with every request on its own
_OTLP_HTTP_EXPORTER_DEFAULT_HEADERS = frozenset({"content-encoding", "content-type", "user-agent"})


def _exporter_headers(exporter: SpanExporter) -> Union[List[Tuple[str, str]], Dict[str, str]]:
    headers: Optional[Union[List[Tuple[str, str]], Dict[str, str]]] = getattr(
        exporter, "_headers", None
    )
    if headers is not None:
        return headers
    client = getattr(exporter, "_client", None)
    client_headers: Dict[str, str] = getattr(client, "_headers", None) or {}
    return {
        key: value
        for key, value in client_headers.items()
        if key.lower() not in _OTLP_HTTP_EXPORTER_DEFAULT_HEADERS
    }

설계에서 고민한 세 가지

  1. 두 위치를 모두 확인합니다. 예전 위치(exporter._headers)에 값이 있으면 그걸 쓰고, 없으면 새 위치(exporter._client._headers)를 봅니다. 그래서 1.43, 1.44, 1.45 어디서나 동작합니다. 당시 저장소의 lock 파일은 1.43이었습니다.
  2. 기본 헤더를 걸러냅니다. 걸러내지 않으면 배너가 아래 첫 줄처럼 바뀝니다. 사용자가 넣지도 않은 헤더가 ****로 가려진 채 보이면 헷갈립니다. 걸러내면 1.44 이하와 똑같이 나옵니다.
  3. 테스트도 같은 헬퍼를 씁니다. 기존 테스트 두 개도 exporter._headers를 직접 읽다가 1.45에서 깨졌기 때문입니다.
# 걸러내지 않았을 때
Transport Headers: {'content-type': '****', 'user-agent': '****', 'authorization': '****'}
# 걸러냈을 때 (1.44 이하와 같음)
Transport Headers: {'authorization': '****'}

추가한 회귀 테스트

HTTP 주소와 인증 헤더로 register()를 부른 뒤, 배너에 헤더 이름만 가려진 채 나오고 토큰 값은 새지 않는지 확인합니다.

def test_register_with_http_endpoint_masks_headers_in_tracing_details(self) -> None:
    tracer_provider = register(
        endpoint="http://localhost:6006/v1/traces",
        headers={"Authorization": "Bearer token123"},
        verbose=False,
        set_global_tracer_provider=False,
    )

    details = tracer_provider._tracing_details()

    assert "Transport: HTTP + protobuf" in details
    assert "Transport Headers: {'authorization': '****'}" in details
    assert "token123" not in details

08메인테이너가 바꾼 부분

메인테이너는 PR을 승인한 뒤, 방향을 조금 바꾸는 커밋을 직접 더했습니다.

  • 호환 분기 삭제: 1.44 이하를 위한 분기를 지우고, phoenix-otel이 opentelemetry-exporter-otlp-proto-http>=1.45.0을 필수로 요구하게 했습니다.
  • 헬퍼 단순화: getattr로 추측하는 대신, isinstance로 HTTP와 gRPC를 명확히 나눴습니다.
  • 저장소 전체 버전 올림: 저장소 전체의 OTel 버전 고정을 1.45.0/0.66b0으로 올리고 lock 파일을 갱신했습니다.
  • 연쇄 문제 처리: opentelemetry-api 1.45의 AttributeValue 타입 별칭을 mypy가 받아들이지 않는 문제도 Phoenix 쪽에서 우회했습니다.

main에 들어간 최종 코드

def _exporter_headers(exporter: SpanExporter) -> Dict[str, str]:
    if isinstance(exporter, _HTTPSpanExporter):
        return {
            key: value
            for key, value in exporter._client._headers.items()
            if key.lower() not in _OTLP_HTTP_EXPORTER_OWN_HEADERS
        }
    if isinstance(exporter, _GRPCSpanExporter):
        headers = exporter._headers
        if isinstance(headers, (dict, list, tuple)):
            return dict(headers)
    return {}
왜 호환성을 버렸을까

호환 분기를 두면 "이 속성이 있을까?" 하고 추측하는 코드가 남고, 테스트해야 할 버전 조합도 늘어납니다. 최소 버전을 올리면 타입이 분명해지고 코드가 짧아집니다. 대신 구버전 OTel을 쓰는 사람은 OTel도 같이 올려야 합니다. 저장소 전체 버전을 올리는 일은 외부 기여자가 하기엔 범위가 커서 메인테이너가 직접 한 것으로 보입니다.

다음 PR에서 참고할 점: 이 팀은 넓은 호환성보다 단순한 코드를 선호합니다.

핵심 아이디어는 그대로 남았습니다. 클라이언트에서 헤더를 읽고, exporter가 스스로 붙인 헤더는 걸러내며, 회귀 테스트로 이를 확인하는 방식입니다.

### Bug Fixes

10배운 점

  1. 내부 속성에 기대는 코드는 업데이트 한 번에 깨진다. 공개 API가 있으면 그걸 쓰고, 없다면 방어 코드와 테스트로 감싸야 합니다.

  5. 머지된 최종 코드와 비교한다. 메인테이너가 무엇을 바꿨는지 보면 그 프로젝트가 무엇을 중요하게 여기는지 보입니다.

11스스로 설명해보기

면접에서 이 PR에 대해 나올 만한 질문입니다. 답을 펼치기 전에 먼저 말로 설명해 보세요.

verbose=False로 배너를 꺼도 왜 register()가 죽었나요?

register()는 배너 문자열(_tracing_details())을 항상 만들고, 출력 여부만 verbose로 정합니다. 배너를 만들면서 exporter._headers를 읽는 순간 AttributeError가 났기 때문에 출력 설정과 상관없이 죽었습니다.

gRPC를 쓰는 사람은 왜 영향이 없었나요?

OTel 1.45의 리팩터링(PR #5389)은 HTTP exporter만 새 공용 HTTP 클라이언트로 바꿨습니다. gRPC exporter에는 _headers 속성이 그대로 있어서 기존 코드가 계속 동작했습니다.

어떻게 재현했나요?

격리된 가상환경에 arize-phoenix-otel 0.17.1과 OpenTelemetry 1.45.0을 설치했습니다. 처음엔 기본값으로 돌렸는데 기본 전송 방식이 gRPC라 재현되지 않았습니다. 신고자처럼 HTTP 주소(http://localhost:6006/v1/traces)를 지정하자 같은 AttributeError가 났습니다. 그 뒤 1.45의 exporter 코드를 열어 헤더가 _client._headers로 옮겨진 것을 확인했습니다.

content-type과 user-agent는 왜 걸러냈나요?

1.45에서는 클라이언트 헤더에 사용자 헤더와 exporter 기본 헤더가 섞여 저장됩니다. 그대로 보여주면 사용자가 넣지 않은 헤더가 ****로 가려진 채 나타나 헷갈립니다. 1.44 이하에서는 기본 헤더가 requests Session에 따로 있어서 _headers에는 사용자 헤더만 있었습니다. 걸러내면 출력이 예전과 같아집니다. 압축을 켜면 붙는 content-encoding도 같은 이유로 걸렀습니다.

테스트는 무엇을 보장하나요?

새 회귀 테스트는 HTTP 주소와 인증 헤더로 register()를 부른 뒤, 배너에 {'authorization': '****'}만 나오고 토큰 값은 없는지 확인합니다. 기존 HTTP 테스트 두 개는 헬퍼로 헤더를 읽도록 바꿔서 OTel 버전과 상관없이 검증되게 했습니다. 수정 전 OTel 1.45에서는 4개가 실패했고, 수정 후에는 1.43, 1.44, 1.45 모두에서 134개가 통과했습니다.

메인테이너는 왜 구버전 호환 코드를 지웠을까요? 단점은 없나요?

호환 분기를 두면 속성이 있는지 추측하는 코드가 남고, 테스트할 버전 조합이 늘어납니다. 최소 버전을 1.45로 올리면 isinstance로 분명하게 나눌 수 있어 코드가 단순해집니다. 단점은 구버전 OTel에 묶인 사용자가 함께 올려야 한다는 점입니다. 예를 들어 OTel을 1.45 미만으로 제한한 W&B Weave와는 한 환경에 같이 설치할 수 없습니다.

내부 속성에 기대는 방식을 아예 없앨 수는 없었나요?

exporter가 헤더를 공개 API로 내주지 않아서 완전히 피하기는 어렵습니다. Phoenix가 exporter에 넘긴 헤더를 따로 보관해 배너에 쓰는 방법도 있습니다. 하지만 OTel이 환경변수(OTEL_EXPORTER_OTLP_HEADERS 등)에서 추가로 읽는 헤더까지 보여주려면 결국 내부를 봐야 합니다. 그래서 내부 속성을 읽되, 테스트로 변화를 바로 잡아내는 쪽을 택했습니다.

이 이슈는 어떻게 찾았고, 왜 이걸 골랐나요?

외부 PR이 실제로 머지되는 저장소를 먼저 측정했습니다. Phoenix는 외부인 PR의 36%가 14일 안에 머지됐고, 중앙값이 2.1일이었습니다. 그중 올라온 지 하루 된 버그 신고를 골랐습니다. 영향이 크고 재현 방법이 분명하며, 아무도 가져가지 않은 상태였습니다. 영향이 큰 만큼 메인테이너가 직접 고칠 수도 있어서, 재현과 수정을 먼저 끝내고 코멘트와 PR을 한 번에 올렸습니다.
